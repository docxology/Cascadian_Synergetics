# Discussion {#sec:discussion}

Showing instead of telling moves the burden of proof from the text to the code.
A lesson can hedge; a brass counter cannot. When the counter clicks out a
volume, the only honest support for it is the computation behind it, run where
it can be inspected and tested against a source that did not come from the same
hands. Here that source is QuadMath's own Python, run once to record its
answers, and QuadCraft's own bytes, pinned by the hash Git gives them.

Two of the three results are known. That four lattice nodes always span a
whole number of tetravolumes [@quadmath], and that the A modules are equal
[@fuller1975], are facts of synergetics that the games only exhibit; what the
repository adds is a check that the games' code agrees with them. The third is a property of a
measurement. The gauge reads the convex hull of the jitterbug's vertices, and
under the games' parametrization that hull grows on leaving the vector
equilibrium before it shrinks. It says nothing about Fuller's account of the
jitterbug beyond the named stations it shares; it says what the dial in the
field station shows, and why the dial's scale runs past the vector
equilibrium's volume.

The games stop short in places. The jitterbug's breathing ends at the
octahedron rather than going on to the tetrahedron. Nothing in the grove counts
in A modules beyond the ants' tetrahedron, and the lattice is the only
structure a player can measure. The screenshots in this paper are captured by
hand, while the other figures are drawn from the code. Each of these is a place
where the same discipline could reach further: a measurement the player can
make, computed by code the tests already hold to its source.
